# Strategic recommendations

## 1. The distribution gap is the biggest finding in this scan

The highest-starred project in the entire signal set is ten markdown files packaged
for a plugin marketplace. Meanwhile eighteen production systems with measured numbers
— a router that cut spend to 42.4% of baseline, a grounding verifier running at 46,279
sentences per second, a benchmark that separates refusal from accuracy — sit in one
repository with no distribution surface at all.

The ecosystem rewards packaging far more than it rewards engineering. We have the
engineering. Packaging is the cheapest, fastest-payback move available and it is first
on the roadmap for that reason.

## 2. Build the thermostat, not another thermometer

Two spend-tracking projects in this scan grew over 60% in 82 days. Both report cost.
Neither reduces it. The break-even escalation rate — the point past which routing to a
cheaper model stops saving money — is arithmetic nobody in this set publishes, and it
converts a dashboard into a decision.

## 3. Attach a denominator to every claim we make

The security frameworks here list attack categories without measured detection rates.
The benchmarks publish accuracy without refusal columns. This is the field's habit and
it is also its weakness: a claim with a denominator is immediately more credible than
a longer claim without one, and it is the thing an enterprise buyer can act on.

## 4. Treat licence as a gate before spending any attention

The most technically interesting project in the scan is non-commercial and cannot be
built on at any price. A delayed-open licence and a no-licence repository are in the
same set. Absorbability is a recorded field here precisely so this check happens
before the enthusiasm rather than after the integration.

## 5. Enter now — position is not fixed

The fastest grower in the set moved +64% in 82 days
from a small base, while the largest project grew far more slowly. Categories where
the small are outrunning the large are categories still being decided.

## 6. Run the scanner on a loop

Growth confidence here is LOW and is capped there by construction, because two
observations fix a rate and not a shape. That constraint lifts on its own as snapshots
accumulate: at five readings the same code reports HIGH. The scanner is the asset —
each run makes every subsequent conclusion more defensible, unattended.
